# 2026-07-22 Galaxy 마이크 실시간 상담 연동 작업 보고서

## 한 줄 결론

오늘 작업으로 **Galaxy 휴대폰을 KDA 상담 시스템의 실시간 고객 마이크로 사용할 수 있게 연결했다.** 휴대폰에서 말한 음성은 Windows 노트북을 거쳐 기존 KDA 백엔드로 들어가고, STT 원문·상담 준비 정보·상담 화면·키패드 입력·통화 종료 후 요약 흐름에서 사용할 수 있다.

이번 구현은 별도 시연 프로그램을 새로 만든 것이 아니라, `mingikim` 브랜치의 기존 고객·상담원·관리자 화면과 기존 분석 파이프라인을 유지하면서 실시간 입력 경로를 추가한 것이다. 따라서 향후 UI가 확정되거나 STT·요약 모델, 상담 서버, 저장 DB가 바뀌더라도 현재 연결부를 확장해서 사용할 수 있다.

## 기존에는 무엇이 부족했나

- 기존 프로젝트는 음성 파일 업로드 또는 내부 데모 데이터 중심이었다.
- 실제 휴대폰 마이크의 음성을 기존 상담 흐름으로 지속 전송하는 경로가 없었다.
- 고객이 말한 내용과 상담원이 말한 내용을 실시간으로 구분해 상담 화면에 쌓기 어려웠다.
- 휴대폰 키패드 입력이 상담 중 데이터로 전달·저장되는 흐름이 없었다.
- 실시간 통화가 끊기거나 다시 시작될 때 이전 통화 데이터가 섞일 위험이 있었다.

## 오늘 실제로 한 일

### 1. Galaxy를 실시간 고객 마이크로 연결

- Galaxy에 설치한 WO Mic의 음성을 Windows의 `WO Mic Device`로 수신한다.
- Windows용 경량 오디오 송신기가 해당 마이크를 자동으로 찾아 음성을 읽는다.
- 음성을 STT에 적합한 PCM16 mono 16 kHz 형식으로 기존 KDA 백엔드에 실시간 전송한다.
- 인터넷이나 클라우드 없이 같은 로컬망에서 동작할 수 있다.
- Windows 방화벽에서 필요한 포트만 허용하는 설치 스크립트를 추가했다.

### 2. 휴대폰 음성을 기존 KDA 상담 흐름에 연결

휴대폰에서 들어온 음성을 별도의 테스트 창에서만 보여주는 것이 아니라 다음 기존 기능에 연결했다.

1. 고객 실시간 발화 원문 생성
2. 상담원 화면의 실시간 STT 표시
3. 고객 문의 요약과 업무 분류
4. 위험 신호와 담당 부서 라우팅
5. 상담 준비 카드 생성
6. 상담 연결 후 고객·상담원 대화 누적
7. 통화 종료 후 전체 상담 요약을 만들 수 있는 데이터 계약

STT 원문을 AI 요약이라고 표시하지 않는다. Ollama의 EXAONE 결과가 정상일 때만 AI 요약으로 사용하고, 모델이 없거나 결과 검증에 실패하면 fallback임을 명확히 구분한다.

### 3. 상담원 발화도 같은 상담 기록에 연결

- 상담원 노트북에서도 별도의 마이크 송신기를 실행할 수 있게 했다.
- 고객 발화는 `customer`, 상담원 발화는 `agent`로 명시해 같은 상담 기록에 시간순으로 합친다.
- 상담원이 연결되기 전에는 상담원 마이크 입력을 받지 않고, 실제 상담 연결 이후부터 처리한다.
- 상담원 송신기만 잠시 끊겼다고 고객 통화를 강제로 종료하지 않는다.

이 구현 덕분에 향후 상담원 헤드셋, 실제 CTI, VoIP 입력으로 바뀌어도 오디오 입력 부분만 교체하고 기존 STT·분석·화면 연결은 재사용할 수 있다.

### 4. Galaxy 키패드 입력 전달과 저장

- Galaxy 고객 화면의 `0-9`, `*`, `#` 입력을 백엔드로 전달한다.
- 접수 단계뿐 아니라 상담원이 연결된 이후에도 키패드 입력이 작동한다.
- `0`을 통화 종료키로 사용하지 않으므로 계좌번호·인증번호 입력에 사용할 수 있다.
- 상담 연결 후 `#`도 일반 키패드 입력으로 처리한다.
- 입력은 상담 ID, 통화 회차, 입력 순번, 단계, 시각과 함께 로컬 SQLite에 저장한다.
- 상담원 화면에는 민감한 전체 번호 대신 마스킹된 값과 저장 여부만 표시한다.
- 공개 HTTP 조회 API로 키패드 원문을 노출하지 않는다.

### 5. 통화가 갑자기 끊기거나 다시 걸리는 경우 보강

- 휴대폰 브라우저가 닫히거나 Wi-Fi가 잠시 끊기면 즉시 통화를 끝내지 않고 재연결 시간을 둔다.
- 고객이 정상 종료한 경우에는 남아 있는 마지막 음성까지 STT 처리한 뒤 종료한다.
- 고객이 갑자기 이탈하고 돌아오지 않으면 유예 시간이 지난 뒤 안전하게 종료한다.
- 같은 상담 ID로 다시 전화해도 이전 발화와 새 발화가 섞이지 않도록 통화 회차를 분리한다.
- 임의의 5초 타이머로 통화를 자동 종료하지 않는다.

### 6. 이 노트북 사양에 맞는 로컬 AI 설정

- STT 기본값은 CPU에서 실행 가능한 faster-whisper `small / int8`로 조정했다.
- 로컬 요약은 Ollama의 `exaone3.5:2.4b`를 기본값으로 사용한다.
- 더 좋은 시연 노트북에서는 환경변수만 바꿔 더 큰 Whisper 또는 EXAONE 모델과 GPU를 사용할 수 있다.
- 모델 이름이 코드와 화면에 강하게 묶이지 않도록 실행 설정으로 분리했다.

### 7. 기존 최신 UI와 다시 통합

- UI 담당자의 최신 `origin/mingikim` 변경분(`a3e3261`)을 기능 브랜치에 병합했다.
- 고객 화면의 최신 자막 표현과 관리자 규정 PDF 업로드 UI를 유지했다.
- 실시간 마이크 기능 때문에 기존 화면 전체를 교체하지 않고 필요한 상태와 연결부만 추가했다.
- 관리자 콘솔에서는 STT부터 분류·위험·카드·라우팅까지 이벤트 진행을 관찰할 수 있다.

## 현재 사용자가 보게 되는 흐름

```text
Galaxy에서 통화 시작
→ 휴대폰 마이크 음성이 Windows로 입력
→ KDA 백엔드로 실시간 전송
→ STT 원문이 고객/상담원 화면에 표시
→ 고객 문의 분석·요약·라우팅
→ 상담 준비 카드 확인
→ 상담원 연결 후 두 사람 발화 누적
→ 키패드 입력 전달·저장
→ 통화 종료 후 마지막 발화 처리와 후처리 데이터 생성
```

## 이후 확장할 때 재사용할 수 있는 부분

| 향후 변경 | 그대로 재사용하는 부분 | 교체·추가할 부분 |
|---|---|---|
| UI 최종 확정 | 실시간 이벤트와 상태 훅 | 카드와 애니메이션 배치 |
| 고성능 시연 서버 | 전체 호출 계약 | Whisper·EXAONE 모델 설정 |
| 실제 상담원 헤드셋 | 상담원 발화 채널 | 입력 장치 설정 |
| 실제 CTI/VoIP | STT·화자·요약·저장 흐름 | 오디오 송수신 어댑터 |
| 운영 DB | DTMF·통화 데이터 계약 | SQLite 저장소 구현 |
| 인증·보안 적용 | 통화 ID와 단계 관리 | 사용자 토큰·암호화·보존 정책 |
| 요약 UI 확정 | 5개 후처리 데이터 계약 | 최종 화면 표현 |

즉, 이번 기능은 WO Mic에만 종속된 임시 화면이 아니다. 현재는 Galaxy와 WO Mic으로 검증하지만, 이후 다른 휴대폰 앱·WebRTC·CTI 입력을 붙일 때도 **마이크 입력 어댑터만 교체하고 기존 KDA 처리 흐름을 유지**할 수 있도록 구성했다.
