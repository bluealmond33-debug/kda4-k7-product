- **원인 [확인]**: Whisper 계열의 전형적 무음 환각. `backend/app/` 전체에 환각 필터가 **존재하지 않음** (`hallucination` grep 무결과). `live_stt.py:1421` 에서 `vad_filter=True`, `min_silence_duration_ms: 350` 만 걸려 있고, 세그먼트 신뢰도 기반 폐기 로직이 없음.
- **조치**:
  1. 환각 스톱워드 리스트 필터 — "감사합니다", "시청해주셔서 감사합니다", "구독과 좋아요", "다음 영상에서 만나요" 등을 **단독 세그먼트일 때만** 폐기.
  2. faster-whisper 세그먼트의 `no_speech_prob > 0.6` 또는 `avg_logprob < -1.0` 이면 폐기.
  3. `_SILENCE_RMS`(현재 350) 기준 무음 버퍼는 STT에 아예 넣지 않도록 게이트 강화.
- **파일**: `backend/app/live_stt.py` (1400~1430 근처 transcribe 호출부, 1730~1745 버퍼 플러시)

### B2. 주민번호 마스킹 안 됨 (계좌번호는 됨) — **P0**
- **원문**: "계좌번호는 되고 주민번호는 마스킹 안됨. → 주민번호도 자릿수 상관없이 마스킹되도록."
- **원인 [확인]**: `pii_guard.py:49` 의 rrn 패턴이 `(\d{6})[-\s]?([1-4]\d{6})` — **정확히 6+7자리, 뒷자리 첫 숫자 1~4**를 요구. STT가 주민번호를 "880214 1234567"이 아니라 "880214 123 4567" / "88 02 14 1" 처럼 끊어 적거나 일부만 인식하면 매칭 실패. 계좌번호 패턴(66~70행)은 `계좌\s*번호` **문맥어 + 8자리 이상** 규칙이 있어 관대해서 잡힘.
- **조치**: 계좌와 동일하게 **문맥어 기반 규칙 추가**.
  - `(주민|주민등록|주민번호|앞자리|뒷자리)[^\d\n]{0,8}(?:\d[-\s,]?){5,}\d` → 자릿수 무관 마스킹
  - 기존 엄격 패턴은 유지(문맥어 없이도 잡는 용도), 문맥어 규칙을 **우선순위 최상단**에 배치
  - 원칙상 "애매하면 마스킹"(모듈 docstring 11행)에 부합
- **파일**: `backend/app/services/pii_guard.py:47~70`

- **원문**: 전형진 "사이트에 보안 연결할 수 없음 / ERR_SSL_PROTOCOL_ERROR" (`https://192.168.1.48:5173`)

- **조치** (택1):

  - 또는 `cloudflared` / `ngrok` 터널로 공인 HTTPS 도메인 사용
  - 또는 Chrome `--unsafely-treat-insecure-origin-as-secure=http://192.168.1.48:5173` 플래그 (임시)
- **파일**: `vite.config.ts`, `docs/LOCAL_DEMO_RUNBOOK.md`(절차 문서화)
