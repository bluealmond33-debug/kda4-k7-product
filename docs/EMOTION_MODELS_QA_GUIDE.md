**올바른 순서:** 역할 분담을 먼저 → 숫자는 그 다음.

## 1. 왜 감정 모델이 두 개나 필요한가요?

### 12살에게 설명한다면

화가 난 사람은 두 종류입니다.

- **뜨거운 분노:** 목소리가 커지고, 빨라지고, 톤이 올라갑니다. → 소리만 들어도 압니다.
- **차가운 분노:** 목소리는 오히려 조용하고 차분한데, 속으로는 굉장히 화나 있습니다. "지금... 장난하세요?"처럼요.

**감정온도** 모델은 첫 번째(뜨거운 분노)를 잘 잡습니다. 목소리가 얼마나 격했는지만 보거든요.
그런데 이 모델은 **두 번째를 원리적으로 못 잡습니다.** 조용한 목소리는 "차분함"으로 읽히니까요.

그래서 **WavLM 분노** 모델을 하나 더 붙였습니다. 이 모델은 소리의 크기가 아니라 목소리에 담긴 더 깊은 특징을 보기 때문에, 조용해도 화가 났다는 걸 알아챌 수 있습니다.

> **한 문장 정리:** 온도계 하나로는 "뜨겁다"만 알 수 있어서, "차갑지만 위험하다"를 알려주는 두 번째 센서를 붙였습니다.

### 서비스에서의 관계 — 덮어쓰지 않고, 올리기만 합니다

```
감정온도(주 판정) ──→ 주의등급 기본값 결정
                          │
WavLM 분노(보조) ──────────┤ "격양도는 낮은데 냉정하게 화났다"고 판단되면
                          └→ 주의등급을 NONE → MEDIUM 으로 한 단계 올림
                             (내리지 못하고, HIGH도 만들지 못함)
```

**이 설계가 중요한 이유:** WavLM이 틀려도 **경고가 사라지지는 않습니다.** 오직 "한 단계 더 조심하세요"만 추가할 수 있습니다. 보조 모델이 주 판정을 망가뜨릴 수 없게 구조적으로 막아둔 것입니다.

# 제1부 · 감정온도 모델 (eGeMAPS + LightGBM)

## 2. 이 모델이 재는 것

**"목소리의 각성도(arousal)"** — 얼마나 격앙됐는지를 `낮음 / 보통 / 높음` 3단계로 매깁니다.

**중요:** 이건 "화났다"가 **아닙니다.** 신나서 흥분해도 높음이 나오고, 슬퍼서 목이 메어도 높음이 나올 수 있습니다. 오직 **목소리의 격함**만 봅니다. 발표에서 "감정온도가 높다 = 화났다"라고 말하면 안 됩니다.

### eGeMAPS가 뭔가요? (12살 눈높이)

목소리를 컴퓨터가 이해할 수 있는 **숫자 88개**로 바꾸는 방법입니다. 마치 건강검진표처럼요.


| eGeMAPS가 재는 것    | 쉬운 설명                   |
| ---------------- | ----------------------- |
| 피치(pitch)        | 목소리가 얼마나 높은가 (도레미의 높낮이) |
| 에너지(energy)      | 얼마나 크게 말하는가             |
| 발화 속도            | 얼마나 빨리 말하는가             |
| jitter / shimmer | 목소리가 얼마나 떨리는가           |


이 88개 숫자를 **LightGBM**이라는 판단기가 받아서 3단계 중 하나를 고릅니다. LightGBM은 "스무고개를 아주 많이 하는 기계"라고 생각하면 됩니다 — "피치가 200보다 높나? 그럼 다음 질문..." 식으로요.

> **왜 최신 딥러닝이 아니라 이런 전통적인 방법을 썼나요?** → 이게 이 모델 이야기의 핵심입니다. 아래 3장에서 자세히 다룹니다.

## 3. 개발 서사 — 세 세대에 걸친 진화

### 🔴 1세대의 실패: "가짜 정답으로 공부하고 있었다"

**문제 상황:** 감정온도에는 **사람이 직접 매긴 정답이 거의 없었습니다.** 사람을 시켜 수만 개 음성에 "이건 격양도 몇 점"을 매기게 하려면 돈과 시간이 엄청나게 듭니다.

**첫 번째 시도:** 그래서 `audEERING`이라는 외부 도구가 자동으로 뽑아주는 **arousal 점수를 "가짜 정답(실버 라벨)"으로 삼아** 모델을 가르쳤습니다.

**결과 — 완전한 실패:**

> "기존 방식은 audEERING arousal을 실버 정답으로 사용했지만 사람 감정온도와 **Pearson 0.078**에 그쳤다."
> — `weak_supervision.py:263`

**Pearson 0.078이 무슨 뜻인가요?** 상관계수는 -1에서 1 사이인데, 0에 가까울수록 "아무 관계 없음"입니다. 0.078은 **사실상 무관계**입니다.

> **12살 비유:** 수학 시험을 준비하는데, 답안지가 사실은 **국어 시험 답안지**였던 겁니다. 아무리 열심히 외워도 수학 점수는 안 오릅니다.

**어떻게 벗어났나:** 팀은 원본 AIHub 데이터(14,606개 클립)를 다시 뒤져서, **이미 5명의 사람 평가자가 1~5점으로 매겨놓은 감정 강도 주석**이 있다는 걸 발견했습니다. 이 5인 평균 점수는 실제 사람이 느끼는 감정온도와 훨씬 잘 맞았습니다. **가짜 정답을 버리고 진짜 사람 라벨로 갈아탄 것**이 1차 고도화입니다.

**이 시점의 잠정 결론:** 그때는 **emotion2vec**(최신 딥러닝 임베딩)이 유망해 보였습니다. 팀도 그렇게 추천했었습니다. → **그런데 이게 2세대에서 뒤집힙니다.**

### 🟡 2세대의 반전: 최신 딥러닝이 전통 방식에 졌습니다

27,467개 규모의 제대로 된 라벨 데이터를 확보한 뒤, 팀은 **4개 후보를 정식으로 붙였습니다** (`ordinal_v3.py:783-935`):


| 후보                         | 특징                 | 판단기          |
| -------------------------- | ------------------ | ------------ |
| ① emotion2vec + 신경망        | 최신 음성 임베딩 (777차원)  | 뉴럴 네트워크      |
| ② emotion2vec + LightGBM   | 최신 음성 임베딩 (777차원)  | LightGBM     |
| ③ **eGeMAPS + LightGBM**   | **전통 음향특징 (88차원)** | **LightGBM** |
| ④ emotion2vec + eGeMAPS 결합 | 둘 다 (865차원)        | LightGBM     |


**결과:**


| 후보                          | Macro F1   | QWK        | High 재현율   |
| --------------------------- | ----------: | ----------: | ----------: |
| emotion2vec + LightGBM      | 0.4242     | 0.0919     | 23.69%     |
| **eGeMAPS + LightGBM (승자)** | **0.5948** | **0.3594** | **48.63%** |


**88개 숫자짜리 전통 방식이, 777차원 최신 딥러닝 임베딩을 크게 이겼습니다.**

> **12살 비유:** 최신형 고성능 계산기(emotion2vec)를 사왔는데, 알고 보니 이 문제에는 옛날부터 쓰던 자와 저울(eGeMAPS)이 훨씬 정확했던 겁니다. 비싸고 새로운 게 항상 좋은 건 아닙니다.

**심사위원이 좋아할 포인트 — 결과를 보고 기준을 만들지 않았습니다:**

선택 규칙과 통과 기준이 **실험을 돌리기 전에 이미 코드에 박혀 있었습니다.**

```
선택 규칙: MAX_REAL_SPEAKER_PAIR_OOF_MACRO_F1_THEN_QWK_THEN_HIGH_RECALL
          (Macro F1 1순위 → 동점 시 QWK → 그다음 High 재현율)

사전 등록 통과 기준: macro_f1 ≥ 0.45, balanced_accuracy ≥ 0.45,
                    qwk ≥ 0.20, high_recall ≥ 0.30
```

즉 "결과 나온 다음에 우리한테 유리한 지표를 골라 자랑한 것"이 아니라, **미리 정해둔 자로 잰 것**입니다. 이건 발표에서 반드시 언급할 가치가 있습니다.

**또 하나의 설계 원칙 — 개인정보를 아예 안 봅니다:**

```json
"text_demographic_topic_used": false
```

**텍스트 내용·성별·나이·지역·상담 주제를 모델 입력에 아예 넣지 않았습니다.** 오직 순수 음향 신호만 씁니다. 이건 우리 프로젝트의 "개인정보는 건물을 나가지 않습니다" 서사와 정확히 맞아떨어집니다.

### 🟢 3세대: 정책 튜닝과 최종 동결

#### (1) 불균형 문제 — "보통"이 62%나 됩니다


| 등급              | 개수         | 비율         |
| --------------- | ----------: | ----------: |
| Low (낮음)        | 7,351      | 26.76%     |
| **Medium (보통)** | **17,153** | **62.45%** |
| High (높음)       | 2,963      | **10.79%** |


**문제:** 모델이 게을러져서 **무조건 "보통"이라고만 답해도 62점**을 받습니다. 정작 우리가 제일 알고 싶은 "높음"은 10.79%밖에 없어서 잘 못 배웁니다.

**해결책 1 — 두 개의 예/아니오 질문으로 쪼갰습니다 (cumulative ordinal):**

3지선다를 바로 풀지 않고, 이렇게 나눴습니다.

```
질문 A: "적어도 보통 이상인가?"   → P(≥1)
질문 B: "진짜 높음인가?"          → P(≥2)

조합:  P(낮음)   = 1 - P(≥1)
       P(보통)   = P(≥1) - P(≥2)
       P(높음)   = P(≥2)
```

> **12살 비유:** "이 사람 기분이 좋아, 보통이야, 나빠?"를 한 번에 묻는 대신 → "좀 안 좋아?" "많이 안 좋아?" 두 번 물어보고 합치는 겁니다. 등급 사이의 순서(낮음 &lt; 보통 &lt; 높음)를 모델이 자연스럽게 이해하게 됩니다.

**해결책 2 — "높음"에 더 신경 쓰라고 가중치를 줬습니다:**

학습할 때 High로 라벨된 데이터에만 추가 점수를 부여했습니다 (`high_weight`).

**해결책 3 — 20개 조합을 전부 실험했습니다:**

```
높음 가중치: 1.0, 1.25, 1.5, 2.0, 2.5   (5가지)
높음 판정 문턱: argmax, 0.30, 0.25, 0.20  (4가지)
→ 총 20개 조합을 전부 화자쌍 5-fold로 평가
```

**최종 채택: 가중치 1.25 + 문턱 0.30**

#### (2) 여기서 정직하게 말해야 할 것 — 목표에 못 미쳤습니다

코드에는 **원래 목표했던 등급표**가 있었습니다 (`demo_selection_v4.py:76-98`):


| 티어                         | 조건                                                                    |
| -------------------------- | --------------------------------------------------------------------- |
| `TARGET_60_RECALL` (1차 목표) | High 재현율 ≥ **60%**, 정밀도 ≥ 35%, Macro F1 ≥ 0.52, clean-전화 재현율 차이 ≤ 6%p |
| `BALANCED_DEMO` (차선)       | 위와 동일하되 재현율 ≥ **55%**                                                 |


**실제 도달:** Clean 57.58%, Telephone 56.09% → **1차 목표(60%)에 미달**, 차선 티어(55%)에 걸렸습니다.

> **Q&amp;A에서 "왜 하필 57%인가요?"라고 물으면:**
> "저희는 60% 회수율을 1차 목표로 잡았지만 도달하지 못했고, 한 단계 아래 기준을 정직하게 채택했습니다. 숫자를 목표에 맞추려고 조정하지 않았습니다."
>
> **이 답변은 감점이 아니라 가점 요인입니다.** 목표를 미리 세워놓고 미달을 인정하는 팀이 훨씬 신뢰받습니다.

#### (3) 시도했다가 안 쓴 것 — 슬라이딩 윈도우 피크

**아이디어:** 통화 전체는 차분해도 **중간에 2초짜리 격앙 순간**이 있을 수 있으니, 2초 창을 1초씩 밀면서 가장 격한 지점(peak)을 찾아 반영하자.

**실험:** peak 반영 비율을 0.20 / 0.35 / 0.50으로 바꿔가며 총 9개 후보를 비교했습니다.

**결과: `peak_alpha = 0.00` — 채택하지 않았습니다.** 충분한 이득이 없었습니다.

> **이것도 발표 소재입니다.** "해봤는데 도움이 안 돼서 뺐다"는 것은 실패가 아니라 **검증된 결론**입니다. 안 되는 걸 확인한 것도 실험 결과입니다.

#### (4) 모델 파일 자체가 "나는 아직 운영에 못 쓴다"고 적어놨습니다

최종 저장된 모델 안에 이런 메타데이터가 박혀 있습니다 (`sliding_window_v4.py:531-552`):

```python
"artifact_status":         "DEMO_FINAL_FROZEN"
"inference_status":        "DEMO_RESEARCH_ONLY"
"production_api_allowed":  False
"production_block_reason": "NO_NEW_REAL_CALL_CENTER_SPEAKER_SESSION_HOLDOUT"
```

> **이게 왜 강력한가:** "왜 SHADOW(참고 신호)로만 쓰나요?"라는 질문에 대해, 사람이 나중에 겸손하게 둘러댄 게 아니라 **모델을 만든 그 순간부터 코드에 새겨진 제약**이라고 답할 수 있습니다. 실제 콜센터 화자로 검증한 적이 없으니 운영 자동판단은 금지 — 만든 사람이 스스로 걸어놓은 잠금장치입니다.

## 4. 데이터 누수를 막은 방법 — 화자쌍 5-fold

### 12살에게 설명한다면

시험 공부를 할 때 **연습문제와 시험문제가 똑같으면** 진짜 실력을 알 수 없습니다.

목소리도 똑같습니다. **같은 사람의 목소리**가 연습(학습)에도 있고 시험(검증)에도 있으면, 모델이 "이 사람 목소리 아까 들어봤는데 그때 정답이 뭐였지?"를 기억해서 맞힙니다. **실력이 아니라 암기입니다.**

### 코드에서 어떻게 막았나

`ordinal_v3.py:30-96`

1. **StratifiedGroupKFold** 사용 — 같은 화자쌍은 절대 학습/검증에 걸쳐 나뉘지 않습니다.
2. **최대 256개의 랜덤 시드를 시도**해서, 5개 그룹의 클래스 분포와 크기가 가장 고르게 나뉘는 분할을 골랐습니다.
3. **하드 assertion으로 이중 확인** — 화자쌍이 여러 fold에 걸치면 **프로그램이 그냥 죽습니다.**

```python
for group in np.unique(groups):
    if len(np.unique(assignment[groups == group])) != 1:
        raise RuntimeError("화자쌍 누수 발견")
```

4. 이 검사가 `ordinal_v3.py:846`과 `demo_selection_v4.py:170`에도 **중복으로** 박혀 있습니다. 한 곳만 믿지 않고 매 단계 재확인합니다.

### 그리고 이것 자체가 고도화 단계였습니다

**1세대 데이터셋에는 화자 ID가 아예 없었습니다.** 그래서 코드가 스스로 이렇게 적어놨습니다:

```
"speaker_session_leakage_gate": "BLOCKED_MISSING_SPEAKER_OR_SESSION_ID"
```

→ **"누수 방지가 원천적으로 불가능함"**이라고 자기 리포트에 기록한 겁니다. 그래서 **화자 정보가 있는 더 나은 데이터로 갈아탄 것 자체**가 하나의 중요한 고도화 단계였습니다.

## 5. 전화 음질 시뮬레이션 — 왜, 어떻게

**왜 했나:** 우리는 **콜센터** 서비스입니다. 깨끗한 마이크 녹음으로만 잘 되는 모델은 쓸모가 없습니다.

**어떻게 했나** (`audio.py:80-84`, `telephony_8k_mulaw_up16k`):

```
16kHz 원본
  → 8kHz로 다운샘플            (전화망은 8kHz입니다)
  → G.711 μ-law 8비트 왕복      (전화 코덱이 소리를 압축하는 방식)
  → 다시 16kHz로 업샘플
```

> **12살 비유:** 소리를 일부러 전화기에 한 번 통과시킨 것처럼 찌그러뜨려 놓고, 그래도 맞히는지 시험 본 겁니다.

**결과 — 거의 차이가 없었습니다:**


| 환경        | Macro F1 | High 재현율 |
| --------- | --------: | --------: |
| Clean     | 0.5638   | 57.58%   |
| Telephone | 0.5633   | 56.09%   |


차이 약 **0.0004** — 전화 음질에서도 성능이 유지됩니다.

**정직하게 덧붙일 것:** 코드 주석에 이렇게 쓰여 있습니다.

> "This is an experiment transform, not a bit-exact telecom codec implementation."

→ **진짜 전화망 코덱을 완벽히 재현한 게 아니라 근사 실험**이며, 실제 통신망의 잡음·에코·말 겹침까지 재현한 것은 아닙니다. 이건 발표에서 먼저 인정하고 가야 합니다.

**추가로:** 학습 데이터 자체를 clean + telephone **두 배로 늘려서** 처음부터 전화 음질에도 강하도록 학습시켰습니다. 그리고 후보 선정 기준에 **"clean과 전화의 재현율 차이가 6%p를 넘으면 자동 탈락"**이라는 규칙을 넣어, 깨끗한 소리에서만 잘 되는 모델은 아무리 점수가 좋아도 못 뽑히게 막았습니다.

### WavLM이 뭔가요? (12살 눈높이)

마이크로소프트가 **엄청난 양의 사람 목소리를 미리 들려주며 훈련시켜놓은 AI**입니다. 우리가 처음부터 가ㅇ


| 층             | 이해하는 수준        | 비유                     |
| ------------- | -------------- | ---------------------- |
| 얕은 층 (3번째)    | "억양이 좀 특이한데?"  | 소리의 결·떨림 같은 **표면적 특징** |
| 중간 층 (6, 9번째) | "말투가 평소랑 다른데?" | 소리와 의미의 **중간 단계**      |
| 깊은 층 (12번째)   | "이 사람 지금 화났다"  | 거의 **의미에 가까운 이해**      |


> **12살 비유:** 어떤 사람의 목소리를 들을 때, 어떤 친구는 "목소리가 떨렸어"라고 하고 다른 친구는 "말투가 화난 것 같았어"라고 합니다. 둘 다 맞는 말이고, **둘 다 들어봐야 제일 정확**합니다.

## 8. 개발 서사 — 네 단계의 진화

### 0단계 🔴 emotion2vec+로 시작 → 기각

가장 먼저 시도한 건 WavLM이 아니라 **emotion2vec+ 임베딩**(768차원 + 네이티브 감정점수 9개 = 777차원)이었습니다. 이 위에 세 가지 판단기를 나란히 붙여봤습니다:

- 로지스틱 회귀 / Ridge (`anger_baselines.py`)
- 작은 MLP (`anger_mlp.py` — docstring: *"Small GPU MLP candidates on **frozen emotion2vec+ features**"*)
- LightGBM (`anger_lightgbm.py`)

**결과: 최종 채택되지 못했습니다.** 감정온도 쪽에서 emotion2vec이 eGeMAPS에 졌던 것과 **정확히 같은 패턴**입니다.

> ⚠️ **정직 표기:** 이 단계의 구체적 수치 리포트는 저장소에 없습니다. 코드 구조로 확인한 사실이며, 수치를 묻는 질문에는 "그 리포트는 담당자(전형진)가 별도 보관 중"이라고 답하는 게 안전합니다.

emotion2vec보다 확실히 좋았습니다. **여기서 WavLM으로 방향이 확정됐습니다.**

### 2단계 🟡 4-head 앙상블 — 배운 게 있는 실패

**아이디어:** 같은 레시피로 모델을 **4개 학습시켜(랜덤 시드만 다르게) 결과를 평균**내면 더 안정적이지 않을까?

`anger_mlp_ensemble.py`는 여러 체크포인트를 받아 시그모이드 확률을 단순 평균합니다. 별도로 `anger_stability_report.py`("WavLM anger MLP seed stability")가 있는 걸 보면, **여러 시드로 반복 실행해 안정성을 확인하는 습관**이 팀에 있었습니다.


| 지표        | single MLP | 4-head 앙상블 | 변화             |
| --------- | ----------: | ----------: | --------------: |
| angry 정밀도 | 0.6926     | 0.7362     | **+0.0436** ⬆️ |
| angry 재현율 | 0.6198     | **0.5997** | **−0.0201** ⬇️ |
| angry F1  | 0.6542     | 0.6610     | +0.0068        |
| Macro F1  | 0.7829     | 0.7895     | +0.0066        |

**해석 — 이게 중요합니다:** 정밀도는 올랐지만 **재현율이 떨어졌고 UAR은 오히려 나빠졌습니다.** 헛경보는 줄었지만 **진짜 화난 사람을 더 많이 놓치게** 된 겁니다.

> **12살 비유:** 같은 수업을 들은 학생 4명한테 같은 문제를 풀게 하고 답을 평균 냈습니다. 4명이 **똑같은 걸 배웠으니 똑같은 실수를 합니다.** 답이 안정적이 되긴 했는데, 아무도 모르던 걸 새로 알게 되진 않았습니다.

**깨달음:** 같은 정보를 보는 모델을 여러 개 평균 내는 건 **분산만 줄일 뿐 새로운 정보를 주지 않는다.** → **정말 다른 정보를 봐야 한다.**

---

### 3단계 🟢 4층 통계 융합 — 최종 채택

**핵심 전환:** 마지막 층 하나만 보지 말고, **깊이가 다른 4개 층을 동시에 보자.**

#### 어떤 층을 골랐나

```python
DEFAULT_LAYERS = (3, 6, 9, 12)   # wavlm_layerwise_embeddings.py:20
```

12층을 **4등분한 지점**입니다 — 얕음(3) → 중간(6) → 중간깊음(9) → 깊음(12). 특정 층을 편애하지 않고 **깊이를 골고루 커버**하는 선택입니다.

각 층에서 시간축으로 **평균(mean)과 표준편차(std)**를 뽑습니다:

- 평균 = "전체적으로 어떤 목소리였나"
- 표준편차 = "얼마나 들쭉날쭉했나" ← **감정 변화를 잡는 핵심**

층당 768 × 2 = **1,536차원**, 4개 층이니 총 4 × 1,536.

#### 어떻게 합쳤나 — 학습형 계층 가중치

`anger_layer_fusion.py:78-93`, `WeightedLayerMLP`:

```python
self.layer_logits = nn.Parameter(torch.zeros(len(LAYERS)))   # 숫자 4개짜리 학습 파라미터
weights = softmax(self.layer_logits)                         # 합이 1이 되는 가중치 4개
fused = Σ (weights[i] × normalized_stats[i])                 # 4개 층을 가중합
output = MLP(fused)                                          # 256 → 64 → 1
```

**초기값이 0**이라 학습을 시작할 때는 4개 층이 **정확히 똑같이 0.25씩** 반영됩니다. 그러다 학습이 진행되면서 모델이 **"이 데이터에서는 어느 깊이의 층이 분노 판단에 더 유용한지"를 스스로 배웁니다.**

> **12살 비유:** 4명의 친구한테 의견을 물어보는데, 처음엔 4명 말을 똑같이 25%씩 듣습니다. 그런데 겪어보니 "3번 친구가 이런 상황에선 제일 정확하네?"를 알게 되면 그 친구 말에 더 비중을 둡니다. **누구 말을 얼마나 믿을지를 경험으로 배우는 것**입니다.

#### 얼마나 꼼꼼히 비교했나

`anger_layer_fusion.py:30-39`에서 **10개 아키텍처 × 2가지 클래스 가중치 = 20개 후보**를 전부 학습·비교했습니다:

- 층별 mean만 쓰는 후보들 (단일층)
- 층별 mean+std 쓰는 후보들 (단일층)
- `mean_4_layers_stats` — 4층 **단순 평균**
- `weighted_4_layers_stats` — 4층 **학습형 가중합** ← **최종 승자**

#### 최종 결과


| 지표           | single MLP | 4-head 앙상블 | **4층 융합 (최종)** |
| ------------ | ----------: | ----------: | --------------: |
| angry 정밀도    | 0.6926     | 0.7362     | **0.7364**     |
| angry 재현율    | 0.6198     | 0.5997     | **0.6476** ⬆️  |
| angry F1     | 0.6542     | 0.6610     | **0.6891**     |
| **Macro F1** | 0.7829     | 0.7895     | **0.8053**     |
| UAR          | 0.7723     | 0.7705     | **0.7921**     |


**앙상블 대비: angry F1 +0.0281, Macro F1 +0.0158**

**왜 이번엔 진짜 개선이 났나:** 앙상블(2단계)은 **같은 걸 본 4명의 평균**이었지만, 융합(3단계)은 **한 명이 4가지 서로 다른 단서를 동시에 보고 종합 판단**합니다. 정밀도는 앙상블 수준으로 유지하면서 **재현율을 크게 회복**(0.5997 → 0.6476)한 것이 그 증거입니다.

## 9. 왜 백본을 얼려뒀나 (frozen vs 파인튜닝)

**파인튜닝을 진짜로 시도했습니다.** `wavlm_partial_finetune.py`는 **717줄**짜리 본격적인 구현입니다:

- WavLM 12층 중 **상위 2개 층만 unfreeze**, 나머지는 고정
- 길이 버킷 배치 샘플러 (패딩 낭비 억제)
- 학습 시 12초 슬라이딩 윈도우 랜덤 크롭, 평가 시 10초 hop 윈도우 전부 통과 후 클립 단위 집계
- 백본 학습률 2e-5 / 헤드 학습률 2e-4로 **10배 차등 적용**
- gradient accumulation, fp16 mixed precision, resumable checkpoint
- 소프트 라벨(`anger_vote_ratio`) 증류 옵션, agreement 기반 샘플 가중치 옵션

**그런데 최종 프로덕션은 frozen을 씁니다.** 이유:

### ① 배포 이식성 — 이게 결정적입니다

```python
# wavlm_partial_finetune.py:313-314
if device.type != "cuda":
    raise RuntimeError("partial fine-tuning requires CUDA for this workflow")
```

**파인튜닝 코드는 CPU에서 아예 실행이 안 됩니다.** 그런데 우리 실시간 서비스는:

```python
# voice_anger.py:59
device=settings.wavlm_anger_device,  # CPU 격리 — whisper(cuDNN)와 충돌 회피
```

**GPU는 실시간 STT(whisper)가 이미 쓰고 있어서 WavLM은 CPU로 밀립니다.** 파인튜닝 모델은 이 조건과 애초에 맞지 않습니다.

### ② 과적합 위험

AIHub 36,665건은 **일반 한국어 감정 음성**이지 은행 상담 음성이 아니고, 화자 독립성도 완전히 보장되지 않습니다(§10). 이런 데이터로 백본까지 풀어서 학습하면 **이 특정 데이터셋의 특성에만 과적합**할 위험이 큽니다.

### ③ 검증 단순성

frozen은 "임베딩 추출 1회 + 작은 MLP"라 SHA-256 고정과 재현성 검증이 쉽습니다. 파인튜닝은 optimizer state, gradient scaler state까지 체크포인트에 실어야 해서 검증할 표면적이 훨씬 넓어집니다.

> ⚠️ **정직 표기 — 반드시 지키세요:** "파인튜닝을 돌려봤더니 Macro F1이 X였다"는 **직접 비교 수치는 저장소에 없습니다.** 위 세 가지는 코드 구조에서 나온 근거 있는 설명이지 실측 비교가 아닙니다.
>
> **Q&amp;A 답변:** "CPU 배포 요구사항, 과적합 리스크, 검증 단순성 세 가지 이유로 frozen을 택했습니다. 다만 두 방식의 직접적인 성능 비교 수치는 아직 뽑지 않았습니다."

## 10. 검증 방법론과 한계

### ⚠️ 화자 독립 검증이 완전하지 않습니다

**문제:** 데이터셋에 **실제 화자 ID가 없습니다.**

**차선책 (`anger_split_validation.py`):** **proxy_group** — 나이·성별이 같은 연속된 녹음 구간을 "아마 같은 사람이겠거니" 묶어서, 최소한 그 묶음이 학습/검증/시험에 걸치지 않게 막았습니다.

**자동 감사 항목:** proxy_group 겹침, wav_id 중복, 오디오 파일 누락, split 간 라벨 비율 편차(임계값 8%p)

**코드가 스스로 적어놓은 한계** (`anger_split_validation.py:143-144`):

> *"Proxy groups are contiguous age/sex runs, not verified speaker identities. A passing audit prevents proxy-group overlap but cannot prove speaker-disjoint evaluation."*

> **12살 비유:** 신분증을 확인한 건 아니지만, **비슷한 사람들끼리는 안 섞이게** 최소한의 안전장치는 걸어뒀습니다. 완벽하진 않다는 걸 알고 있고, 그렇게 문서에 적어놨습니다.

### 🟢 테스트셋 오염을 구조적으로 막았습니다 — 이건 자랑해도 됩니다

`anger_layer_fusion.py`의 `run_layer_fusion`은 20개 후보를 비교할 때 **test를 아예 건드리지 않습니다:**

```python
"test": None,
# 주석: "Test is intentionally not evaluated in this validation comparison."
```

별도 함수 `evaluate_saved_test()`가 **최종 선정된 모델 1개**에 대해서만, **validation에서 고정한 문턱 그대로** 딱 한 번 test를 채점합니다:

```python
"threshold_source": "selected validation threshold (fixed; not retuned on test)"
```

> **12살 비유:** 시험문제를 미리 훔쳐보고 거기 맞춰 공부하는 걸 **구조적으로 불가능하게** 만들었습니다. 시험지는 딱 한 번, 마지막에만 열어봅니다.

이건 심사에서 **매우 강한 방법론 점수**가 됩니다. "test로 20번 실험하고 제일 좋은 걸 골랐죠?"라는 의심을 코드로 반박할 수 있습니다.

### 오류 분석 설계 (`anger_error_analysis.py`)

- **놓친 분노(FN)**를 사람이 매긴 강도 구간별로 분해 (50미만 / 50-70 / 70-90 / 90-100)
- **헛경보(FP)**를 실제 라벨별로 분해
- 모든 오류를 **annotation_agreement**(사람 라벨러들끼리 얼마나 합의했는지)별로 분해

**목적:** "낮은 강도의 분노를 놓치는 경향인가" vs "애초에 사람도 헷갈려한 케이스에서 오류가 몰리는가"를 구분하기 위함입니다.

**코드가 적어놓은 한계:**

> *"The manifest has no transcript, so semantic causes cannot be determined... Audio review is required..."*

→ **왜 틀렸는지 자동으로는 알 수 없고, 사람이 직접 오디오를 들어봐야 합니다.**

## 11. 실시간 서비스에서의 동작

### 추론 시간 5.1초의 정체

`WavLMLayerFusionRuntime`은 **매 호출마다 raw WAV를 받아 WavLM 백본을 처음부터 다시 돌립니다** (임베딩 캐시 없음). 백본 forward pass 자체가 무겁고, **CPU에서 돌기 때문에** 약 5.1초가 걸립니다.

**그래서 실시간 주 판정이 아닌 보조로 둡니다.** 통화 중 매초 판정하기엔 너무 느립니다.

### 프로덕션 코드에 박아둔 제약 (`wavlm_layer_fusion_runtime.py:195, 197`)

**모든 예측 응답에 다음이 하드코딩되어 나갑니다:**

```json
{
  "probability_calibrated": false,
  "usage_restriction": "support signal only; excluded from S/G/E routing and counselor assignment"
}
```

> **이게 왜 강력한가:** "이 신호를 상담 라우팅이나 상담사 배정에 쓰면 안 된다"는 제약이 **문서가 아니라 API 응답 자체에 박혀 있습니다.** 나중에 누가 실수로 이 값을 라우팅에 쓰려고 해도, 응답에 "쓰지 말 것"이라고 적혀서 옵니다.

또한 `probability_calibrated: false`는 **"이 확률값 0.858은 '85.8% 확실하다'는 뜻이 아니다"**를 명시하는 것입니다. calibration(확률 보정)을 아직 안 했기 때문에, 순위는 믿을 수 있어도 절대값은 그대로 해석하면 안 됩니다.

### 안전한 폴백

torch/transformers 의존성이나 체크포인트가 없으면 **조용히 `None`을 반환**해서 fusion 로직이 무해하게 넘어갑니다. 감정온도 모델과 **동일한 철학**입니다 — 모델이 없다고 서비스가 죽지 않습니다.

> **발표 프레이밍:** "비운영"이 아니라 **"GPU 환경 조건부 운영 + 안전 폴백"**입니다. 이 랩탑에서는 실제로 돕니다(실측 `REAL_MODEL`, `prob 0.858`). 다른 PC나 배포 환경에서는 자동 폴백합니다. **환경에 맞춰 갈아끼우는 설계 성숙도**로 말하세요 — pgvector/FAISS를 환경에 따라 바꿔 쓰는 것과 같은 논리입니다.

발표에서 "왜 하필 이 모델들인가"를 물으면 쓸 수 있는 논리입니다.

### ① 온프레미스 제약이 모델 선택을 결정했습니다

우리 프로젝트의 제1원칙은 **"개인정보는 건물을 나가지 않는다"**입니다. 이것이 모델 선택에 직결됩니다:


| 제약                    | 그래서 내린 선택                                            |
| --------------------- | ---------------------------------------------------- |
| 외부 API 호출 불가          | 클라우드 감정분석 API(Google, AWS 등) 전면 배제                   |
| GPU는 STT(whisper)가 선점 | 감정온도는 **CPU만으로 도는 eGeMAPS+LightGBM** / WavLM은 CPU 격리 |

> **강력한 한 줄:** "저희가 전통적인 eGeMAPS를 쓴 건 구식이라서가 아니라, **CPU에서 14MB로 돌면서 개인정보를 하나도 안 보는 모델**이 온프레미스 콜센터라는 조건에 정확히 맞았기 때문입니다. 그리고 실제 성능 대결에서도 최신 임베딩을 이겼습니다."

### ② 최신 기술을 무비판적으로 쓰지 않았습니다

emotion2vec(최신 음성 감정 임베딩)을 **두 트랙 모두에서 먼저 시도했고, 두 번 다 기각했습니다.** 감정온도에서는 eGeMAPS에 0.4242 vs 0.5948로 명확히 졌고, 분노에서는 WavLM에 밀렸습니다.

> **"왜 SOTA 모델을 안 썼나요?"에 대한 답:** "썼습니다. 먼저 써보고, 저희 데이터에서 성능이 안 나와서 뺐습니다. 유행이 아니라 측정 결과로 골랐습니다."

### ③ 대체가 아니라 보조 — AI 신뢰성 논의와 정확히 맞습니다

금융권에서 AI 자동 판단은 규제·신뢰 양쪽에서 민감한 주제입니다. 우리 모델은:

- 모델 파일 자체가 `production_api_allowed: False`
- API 응답 자체가 `usage_restriction: support signal only`
- 보조 모델은 경고를 **올릴 수만 있고 내릴 수 없음**

**"AI가 결정하지 않는다"를 슬로건이 아니라 코드로 구현했습니다.** 이건 지금 시점의 AI 도입 담론과 정확히 맞아떨어집니다.

## 13. Q&amp;A 예상 질문 — 답변 스크립트

### 🔥 최빈출

**Q. WavLM이 0.805, 감정온도가 0.564인데 왜 더 좋은 걸 주력으로 안 쓰나요?**

> 두 모델은 **다른 문제를 풀고 있어서 점수를 직접 비교할 수 없습니다.** WavLM은 화났다/안 화났다 2지선다이고, 감정온도는 낮음/보통/높음 3단계입니다. 데이터도 다르고 평가 기준도 다릅니다. 게다가 WavLM은 CPU에서 한 번 추론에 5.1초가 걸려서 실시간 주 판정으로는 못 씁니다. 그래서 **가볍고 항상 도는 감정온도가 주 판정, 무겁지만 정확한 WavLM이 조건부 보조**입니다.

**Q. 감정온도 Macro F1 0.564면 정확도 56%인가요?**

> 아닙니다. Macro F1은 정확도와 다른 지표입니다. **실제 정확도는 64.29%**입니다. Macro F1은 세 등급의 F1 점수를 단순 평균한 것이라, 데이터가 적은 High 등급의 낮은 점수가 그대로 반영돼서 더 낮게 나옵니다. **일부러 어려운 기준으로 보고하고 있는 것**입니다.

**Q. 정밀도가 37%면 열 번 중 여섯 번은 틀린 거 아닌가요?**

> 맞습니다, 의도적입니다. 저희는 **진짜 화난 고객을 놓치는 비용이 헛경보 비용보다 훨씬 크다**고 판단해서 문턱을 30%로 낮게 잡았습니다. 불이 안 났는데 울리는 화재경보기가 짜증나긴 해도, 불이 났는데 안 울리는 것보단 낫습니다. **그리고 바로 이 헛경보율 때문에 자동 판단에 쓰지 않고 상담사 참고용으로만 제한**한 것입니다.

**Q. 실제 콜센터 데이터로 검증했나요?**

> **아니요, 안 했습니다.** 학습·검증 데이터는 AIHub의 일반 한국어 감정 음성이고, 실제 은행 상담 음성이 아닙니다. 그래서 모델 파일 자체에 `production_api_allowed: False`, 차단 사유로 `NO_NEW_REAL_CALL_CENTER_SPEAKER_SESSION_HOLDOUT`을 적어뒀습니다. **비식별 실통화 holdout 구축이 로드맵 3단계**입니다.

**Q. 왜 최신 딥러닝 대신 eGeMAPS 같은 옛날 방식을 쓰나요?**

> 최신 방식(emotion2vec)을 **먼저 써봤고, 저희 데이터에서 명확히 졌습니다.** Macro F1 0.4242 대 0.5948입니다. 게다가 eGeMAPS는 CPU만으로 돌고 모델이 14MB밖에 안 돼서, GPU를 STT가 선점한 온프레미스 환경에 훨씬 잘 맞습니다. **유행이 아니라 측정 결과로 골랐습니다.**

### ⚠️ 아픈 질문 (반드시 준비)

**Q. hybrid50 검증에서 상관계수가 -0.35 음수라던데요?**

> 사실입니다. 사람이 라벨링한 46개 클립과 대조했을 때 음의 상관이 나왔고, 예측의 87%가 medium에 쏠렸습니다. **원인은 그 검증셋이 학습에 쓴 27.5K 데이터가 아닌 구버전 데이터라는 도메인 불일치로 추정하지만, 아직 확정하지 못했습니다.** 이 결과를 알고 있기 때문에 감정온도를 상담카드의 주의등급 산정에서 제외하고 shadow 보조신호로만 두고 있습니다.

**Q. WavLM 파인튜닝은 왜 안 했나요?**

> 시도했습니다. 상위 2개 층만 푸는 partial finetune을 717줄로 구현했습니다. 최종적으로 frozen을 택한 이유는 세 가지입니다. 첫째, 파인튜닝 코드는 **CUDA가 필수**인데 저희 실시간 서비스는 GPU를 whisper가 써서 WavLM이 CPU로 밀립니다. 둘째, 일반 감정 음성 데이터에 백본까지 맞추면 과적합 위험이 큽니다. 셋째, frozen이 재현성 검증이 훨씬 단순합니다. **다만 두 방식의 직접 성능 비교 수치는 아직 뽑지 않았습니다.**

**Q. 화자 독립 검증은 됐나요?**

> **완전하게는 안 됐습니다.** WavLM 데이터셋에 실제 화자 ID가 없어서, 나이·성별이 같은 연속 구간을 proxy로 묶어 그 묶음이 학습/시험에 걸치지 않게만 막았습니다. 코드에도 *"cannot prove speaker-disjoint evaluation"*이라고 명시해뒀습니다. 반면 **감정온도 쪽은 화자쌍 정보가 있어서 제대로 된 화자쌍 5-fold를 적용**했고, 누수가 발견되면 프로그램이 죽도록 assertion까지 걸어놨습니다.

**Q. 20개 후보 중에 제일 좋은 걸 test로 고른 거 아닌가요?**

> 아닙니다. **후보 비교 단계에서는 test를 아예 평가하지 않습니다.** 코드에 `"test": None`과 *"Test is intentionally not evaluated in this validation comparison"*이라고 명시돼 있고, 최종 선정된 모델 1개에 대해서만 **validation에서 고정한 문턱 그대로** 딱 한 번 test를 채점합니다. 문턱을 test에 맞춰 재조정하지 않았다는 것도 코드에 기록돼 있습니다.

**Q. 전화 음질 검증했다는데 진짜 전화망인가요?**

> 아닙니다. 16kHz를 8kHz로 낮추고 G.711 μ-law 코덱을 왕복시킨 **근사 시뮬레이션**입니다. 코드 주석에도 *"not a bit-exact telecom codec implementation"*이라고 적어뒀습니다. **실제 통신망의 잡음·에코·말 겹침까지 재현한 것은 아닙니다.**

### 💡 방법론 질문 (가점 기회)

**Q. 데이터 누수는 어떻게 막았나요?**

> 감정온도는 **StratifiedGroupKFold로 화자쌍 단위 5-fold**를 썼습니다. 같은 화자쌍이 학습과 검증에 걸치면 프로그램이 죽도록 assertion을 걸었고, 그 검사를 **세 군데에 중복으로** 넣었습니다. 그리고 fold 분할 자체도 최대 256개 시드를 시도해서 클래스 분포가 가장 고른 걸 골랐습니다. 참고로 초기 데이터셋에는 화자 ID가 아예 없어서 코드가 스스로 `BLOCKED_MISSING_SPEAKER_OR_SESSION_ID`라고 기록했었고, **화자 정보가 있는 데이터로 갈아탄 것 자체가 하나의 고도화 단계**였습니다.

**Q. 하이퍼파라미터는 어떻게 정했나요?**

> 감정온도는 **High 가중치 5가지 × 판정 문턱 4가지 = 20개 조합**을 전부 화자쌍 5-fold로 돌려서 골랐습니다. 선택 기준도 미리 코드에 등록해뒀습니다 — Macro F1 1순위, 동점이면 QWK, 그다음 High 재현율 순입니다. WavLM은 **10개 아키텍처 × 2가지 클래스 가중치 = 20개 후보**를 비교했습니다.

**Q. 목표 성능은 달성했나요?**

> **1차 목표는 미달했습니다.** 코드에 `TARGET_60_RECALL`(High 재현율 60%)이라는 티어를 미리 정의해뒀는데, 실제로는 57.58%가 나와서 한 단계 아래인 `BALANCED_DEMO`(55%) 티어에 걸렸습니다. **숫자를 목표에 맞추려고 조정하지 않고, 미달한 채로 정직하게 채택했습니다.**

**Q. 시도했다가 버린 게 있나요?**

> 여러 개 있습니다. ① audEERING arousal을 가짜 정답으로 쓰는 방식 — 사람 라벨과 상관 0.078로 사실상 무관해서 폐기. ② emotion2vec — 두 트랙 모두에서 시도했으나 성능으로 기각. ③ 슬라이딩 윈도우 피크 보정 — 통화 중간의 격앙 순간을 잡으려 했으나 이득이 없어 `peak_alpha=0`으로 비활성화. ④ WavLM 4-head 앙상블 — 정밀도는 올랐지만 **재현율과 UAR이 오히려 떨어져서** 층 융합으로 방향을 틀었습니다. ⑤ WavLM partial finetune — 구현은 했으나 CPU 배포 요구사항과 안 맞아 frozen 채택.
