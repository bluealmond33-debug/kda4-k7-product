# K7 팀 현황 공유 · 2026-07-20

## 지금 만드는 것

**K7 CallBrief는 완료된 한국어 은행 상담 음성을 폐쇄망 노트북에서 분석해,
상담사가 통화 전에 확인할 요약·고객 요청·추가 확인 정보·사고징후·절차와
근거를 한 장의 준비 카드로 만드는 상담사 지원 데모다.**

AI 상담사나 콜센터 전체 시스템이 아니며, 지급정지·본인확인·원장 조회를
직접 실행하지 않는다. 최종 판단과 실제 업무 처리는 상담사가 한다.

## 오늘 확인된 실제 실행 상태

- 브랜치: `lch`만 사용, `main` 미변경
- 실행 주소: 서버 노트북 `http://127.0.0.1:8080`, 같은 LAN `http://<IPv4>:8080`
- 구성: React/Nginx → FastAPI → faster-whisper → 로컬 RAG → Ollama/EXAONE 2.4B → 안전 규칙 → 일반업무 주제 모델 → PostgreSQL
- 실음성: `성질.m4a` 업로드부터 카드·DB 저장까지 성공
- 최신 관찰 지연: 약 1분 49초(1회 관찰값, 성능 보장 아님)
- 테스트: 호스트 백엔드 52개 이상 통과, 프론트 계약·타입·프로덕션 빌드 통과
- 감정 분석: 미연동이 정상이며 임의 점수를 표시하지 않음

## 전형진 님 모델의 정확한 통합 범위

전달 ZIP에서 확인된 것은 다음 세 파일이다.

- `bank_topic_classifier.joblib`
- `requirements-ml.txt`
- `bank_topic_metrics.json`

모델 SHA-256은
`0474677A2C335817F9F677A37077C3E56C81BD2CB3378E506B6479910A263832`와
일치한다. 백엔드는 해시를 확인한 뒤에만 `joblib`을 로드한다.

성능 수치의 의미는 다음과 같다.

- NIA 은행 일반업무 10종 전체 정확도: `74.2%`
- margin `0.75` 이상 고확신 구간 정확도: `90.4%`
- 고확신 자동 분류 범위: 검증 데이터의 `61.3%`
- margin 미달: `G004 기타·복합 일반 상담` 폴백

이 수치는 긴급·단순·일반 전체 라우팅이나 ARS 17종의 정확도가 아니다.
긴급·단순·ARS 17종은 규칙 테스트 통과 설명만 확인했고, 관련 코드와
학습 코드는 이번 ZIP에 없었다. 실제 발화 정확도 평가도 별도 과제다.

실음성 보이스피싱 사례에서 일반업무 모델은 `거래내역/잔액조회`를
예측했지만 margin `0.046`으로 G004 폴백됐다. 최종 카드는 안전 규칙의
`금융사기/high`가 우선했고 DB에는 `application=incident_priority`로 남았다.

- 감정 모델 미연동, 사고징후, RAG 근거, API 오류 상태를 거짓 더미 없이 표시

## 다음 작업 순서

### P0 · 발표가 끊기지 않는 데모

1. 동기식 2분 대기를 `업로드 → job_id 반환 → 진행상태 조회 → 카드 완료`로 변경한다.
2. 승인된 한국어 테스트 음성 10~20건과 기대 결과표를 만든다.
3. 카드의 `추가 확인`을 긴 문단이 아닌 항목 목록으로 분리한다.
4. 보이스피싱·무단이체·대출·환전·착오송금 회귀 테스트를 고정한다.
5. 발표용 3분 시나리오와 실패 시 복구 순서를 문서화한다.

### P1 · 모델을 믿을 수 있는 근거 만들기

1. 일반업무 10종의 팀 보유 음성 기준 confusion matrix와 coverage를 다시 측정한다.
2. 긴급·단순·ARS 코드 전체와 라벨 정의를 전달받아 별도 축으로 연결한다.
3. `LLM 결과`, `안전 규칙`, `주제 모델`, `RAG 근거`의 출처를 카드 JSON에서 구분한다.
4. 실제 상담사 3명 이상에게 정보 순서·누락·과잉 경고를 인터뷰한다.

### P2 · 장기 비전 검증

CTI/SIP, 고객 동의, 인증, 원장, 금융사고 접수 연동은 현재 MVP가 유용하다는
증거가 나온 뒤 별도 아키텍처와 보안 요구사항으로 설계한다.

## 역할 제안

- 제품·도메인: 시나리오, 금지 표현, 완료 기준, 발표 서사
- 프론트·UX: 카드 정보 위계, 로딩·실패·재시도, LAN 브라우저 검증
- 백엔드·플랫폼: 비동기 작업, 컨테이너, 모델 호출, 장애 처리
- STT·LLM: 전사·구조화 품질, 프롬프트, 모델 응답 규격
- 라우팅 모델: 라벨 정의, threshold, 실제 발화 평가, 모델 전달물
- 데이터·통합: 계약, DB, `call_id`, 모델 provenance, E2E 품질 게이트

이찬희 역할은 단순 DB 보조가 아니라 **데이터 계약·DB·프론트/백엔드/모델
연결·E2E 품질 게이트를 소유하는 통합 역할**로 두는 것이 맞다.
