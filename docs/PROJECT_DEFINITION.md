# K7 CallBrief 제품 정의 및 실행 기준

> 상태: 2026-07-20 기준 · `lch` 브랜치 실행본의 단일 기획 기준

## 1. 한 문장 정의

**완료된 한국어 은행 상담 음성파일을 노트북 폐쇄망에서 STT·LLM·안전 규칙·로컬 RAG로 분석해, 근거가 보이는 상담 준비 카드·체크리스트·스크립트를 만들고 `call_id`로 저장하는 상담사 지원 데모**

가칭 제품명은 **K7 CallBrief**다. “콜센터 전체 시스템”이나 “AI 상담사”가 아니라, 상담사가 통화를 시작하기 전에 맥락을 빠르게 파악하도록 돕는 **상담 준비 도구**다.

## 2. 해결하려는 문제

상담 연결 전 고객 문의가 구조화되어 상담사에게 전달되지 않으면 상담사는 연결 직후부터 문의 목적, 고객 요청, 누락 정보, 사고 징후를 다시 파악해야 한다. 이 때문에 초반 확인 질문이 반복되고 중요한 위험 신호를 놓칠 수 있다.

현재 프로젝트가 검증할 가설은 하나다.

> 상담 전에 고객 발화를 근거와 함께 한 장의 준비 카드로 제공하면, 상담사는 더 빠르고 안전하게 첫 질문과 처리 순서를 결정할 수 있다.

실제 상담시간 단축이나 재이관 감소는 아직 입증된 성과가 아니다. 현장 상담사 인터뷰와 비교 실험 전까지는 **검증할 기대효과**로만 표현한다.

## 3. 현재 MVP와 장기 비전의 경계

| 구분 | 현재 실제 실행본 | 장기 비전 |
|---|---|---|
| 입력 | WAV·MP3·M4A 등 완료된 음성파일 업로드 | CTI/SIP 통화 및 대기 중 고객 발화 |
| 처리 | 전체 파일 일괄 처리 | 통화·대기열과 연동된 실시간 또는 준실시간 처리 |
| 사용자 | 상담사 화면 중심 데모 | 고객 사전접수와 상담사 업무화면 연결 |
| 출력 | 전사문, 상담카드, 체크리스트, 스크립트, RAG 근거 | 실제 상담 라우팅·업무시스템 보조 |
| 업무 실행 | 상담사가 판단하는 안내용 초안 | 승인된 은행 시스템과 제한적 연동 |

발표와 문서에서는 두 열을 섞지 않는다. 현재 MVP는 장기 비전의 핵심 가설만 검증하는 기술 데모다.

## 4. 현재 데이터 흐름

```text
음성파일 업로드
→ faster-whisper 한국어 STT
→ K7 시연용 업무가이드 검색(RAG)
→ 검색 근거를 포함한 Ollama/EXAONE 구조화 분석
→ 금융사고 안전 규칙
→ NIA 일반업무 10종 주제 분류(고확신만 채택, G004 폴백)
→ mvp-1.1 계약 검증
→ PostgreSQL 3테이블 저장
→ React 상담 준비 카드·통화 스크립트 표시
```

활성 API는 `POST /api/v1/calls`, `GET /api/v1/calls/{call_id}/consultation-card`, `GET /health`다. 프론트엔드와 모델은 DB에 직접 연결하지 않고 FastAPI만 PostgreSQL에 접근한다.

## 5. 상담 준비 카드의 필수 출력

- 고객 발화 전사문과 음성 길이
- 문의 요약
- 고객이 실제로 요청한 내용
- 추가 확인이 필요한 정보
- 업무 유형과 전달 부서, 전달 근거
- 사고 징후 `low | high`와 판단 근거
- 상담 전 확인 체크리스트
- 통화 중 단계별 상담 스크립트
- 사용한 로컬 업무가이드 제목·구간·발췌·검색점수
- `call_id`, 생성시각, DB 재조회 결과

## 6. 반드시 지키는 판단 경계

1. AI는 초안을 만들고 상담사가 최종 판단한다.
2. 위험도는 고객 발화의 사고 징후와 안전 규칙으로 판단한다. 목소리가 크다는 이유로 고위험 또는 감정 고조로 분류하지 않는다.
3. 음성 감정 모델이 연결되지 않은 동안 감정 점수를 만들지 않고 `unavailable`로 표시한다.
4. RAG 자료는 현재 K7 시연용 가이드다. 실제 은행 내부 규정이라고 소개하지 않는다.
5. 지급정지, 계좌 차단, 본인확인 완료, 고객 원장 조회를 실제 수행했다고 표시하지 않는다.
6. 개인정보 마스킹, 고객 마스터, 권한·감사로그, 상담사 자동배정은 현재 MVP 필수 범위가 아니다.
7. 일반업무 주제 모델의 성능 수치를 긴급·단순·일반 전체 또는 ARS 17종
   라우팅 성능으로 확대 해석하지 않는다.

## 7. 2026-07-20 구현 현황

| 영역 | 상태 | 판단 |
|---|---|---|
| React/Nginx 상담 화면 | 완료 | 실제 API 응답으로 주요 카드·스크립트·RAG 표시 |
| FastAPI `mvp-1.1` API | 완료 | 업로드·처리·저장·재조회 경계 동작 |
| faster-whisper 한국어 STT | 완료 | 로컬 `small`/CPU `int8` 프로필 동작 |
| Ollama/EXAONE 분석 | 완료 | 요약·요청·누락정보·업무유형·위험·행동 초안 생성 |
| 안전 규칙 | 완료 | 금융사고 키워드와 과도한 처리 단정 보정 |
| 일반업무 주제 분류 | 통합 완료 | NIA 10종 모델, SHA 검증, margin 0.75 미만 G004 폴백; 사고징후 라우팅 우선 |
| 긴급·단순·ARS 17종 규칙 | 코드 미전달 | 규칙 테스트 통과 설명만 확인; 실제 발화 정확도와 통합은 미완료 |
| 로컬 RAG | 데모 완료 | K7 시연용 문서 검색; 실제 은행 규정 아님 |
| PostgreSQL | 완료 | `calls`, `transcripts`, `consultation_cards` 저장·재조회 |
| 폐쇄망 실행 | 완료 | 데이터 처리망 내부화, 프론트 8080만 LAN 공개 |
| 음성 감정 모델 | 미연동 | 점수 미생성, `모델 미연동` 표시가 정상 |
| CTI/SIP·실시간 통화 | 미구현 | 음성파일 일괄 처리만 지원 |
| 실제 은행 업무시스템 | 미구현 | 원장 조회·본인확인·지급정지·민원 접수 실행 안 함 |

실제 `성질.m4a` 파일로 음성 업로드부터 카드·스크립트·RAG·DB까지 E2E가 동작했다. CPU 노트북의 EXAONE 2.4B 반복 실행에서 관찰된 전체 처리시간은 약 1분 49초~2분 46초였으며, 이는 소수 관찰값이지 성능 보장 수치가 아니다. 동기식 요청의 긴 대기는 다음 구조 개선 대상이다.

일반업무 주제 모델의 제공 평가값은 전체 정확도 `74.2%`, margin `0.75`
이상 구간 정확도 `90.4%`, 해당 구간의 검증 데이터 범위 `61.3%`다.
긴급·단순·일반 전체와 ARS 17종은 규칙 테스트만 통과한 상태로 전달받았고,
실제 발화 기준 정확도 평가는 별도로 해야 한다.

## 8. 데모 완료 기준

다음 조건을 모두 충족해야 “동작하는 MVP”라고 말한다.

- 정상·사고 의심·대출·전자금융 등 승인된 한국어 음성 10건 이상이 끝까지 처리된다.
- 모든 응답이 `mvp-1.1` 계약을 통과하고 POST와 GET의 `call_id`·카드가 일치한다.
- 고위험 시나리오에서 사고 징후와 상담사 확인 절차가 누락되지 않는다.
- 카드의 주요 사실이 전사문, 안전 규칙 또는 표시된 RAG 자료로 추적 가능하다.
- 모델 장애·DB 장애·지원하지 않는 파일에 대해 거짓 fixture가 아니라 명확한 오류가 보인다.
- 인터넷을 끈 상태에서 서버 노트북과 같은 LAN의 다른 기기에서 데모가 열린다.
- 실제 은행 연동이 아닌 기능에는 데모·미연동 라벨이 보인다.

## 9. 우선순위

### P0 — 발표 가능한 한 줄 제품 만들기

- 승인된 테스트 음성 10~20건과 기대 결과표 작성
- 위험 시나리오 안전 체크와 환각 사례 회귀 테스트
- 카드 각 필드의 근거 출처를 UI와 결과 JSON에서 확인
- 로딩·실패·재시도·초기화 동작 정리
- 발표용 3분 E2E 시나리오 고정

### P1 — 데모 신뢰도 높이기

- K7 가이드를 출처가 명확한 공개 금융 자료 또는 승인된 내부 모의 규정으로 교체
- 시나리오별 분류·요약·누락정보·위험도 평가표 운영
- CPU 지연시간 측정과 모델 크기·양자화 비교
- 상담사 3명 이상에게 카드 유용성·불필요 항목 인터뷰

### P2 — 제품 비전 검증

- 대기 중 사전발화 UX와 고객 동의·철회 설계
- CTI/SIP 연결 가능성 조사
- 실제 은행 인증·원장·사고 접수 시스템의 연동 경계 정의
- 현행 방식과 준비 카드 방식의 첫 질문 도달시간·누락률 비교

## 10. 역할은 기술명이 아니라 산출물로 나눈다

| 역할 | 책임 산출물 |
|---|---|
| 제품·도메인 | 문제 정의, 시나리오, 금지 표현, 완료 기준, 발표 서사 |
| 프론트엔드·UX | 실제 API 연결, 카드·스크립트·근거·오류 상태, LAN 브라우저 검증 |
| 백엔드·플랫폼 | FastAPI, 컨테이너, 네트워크, 모델 호출, 장애 처리 |
| STT·LLM | 전사·구조화 분석 품질, 프롬프트, 모델 응답 규격 |
| 데이터·통합 | `mvp-1.1` 계약, PostgreSQL, `call_id`, 저장·재조회, E2E 품질 게이트 |
| 지식·평가 | RAG 자료 출처, 테스트셋, 기대 결과, 회귀 평가 |

따라서 이찬희의 역할은 막연한 “DB” 보조가 아니라 **데이터 계약·DB·프론트/백엔드/모델 연결·E2E 품질 게이트를 소유하는 통합 역할**로 정의한다.

## 11. 발표용 설명

> K7 CallBrief는 AI가 은행 업무를 처리하는 서비스가 아닙니다. 고객의 완료된 상담 음성을 폐쇄망 노트북에서 분석해, 상담사가 통화 전에 확인할 요약·요청·누락정보·사고징후·절차와 근거를 한 장으로 만드는 상담 준비 데모입니다. 최종 판단과 실제 업무 처리는 상담사가 수행합니다.
