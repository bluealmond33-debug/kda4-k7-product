## 0. 흐름

부서를 축으로 **배정(왼쪽)**과 **검색(오른쪽)**이 한 줄에서 만난다.

```
        ┌──────── 배정(routing) ────────┐   ┌─── 검색(RAG) ───┐
부서  →  S/G/E  →  task_code  →  handler  │  business_code → 문서
        └──────────────────────────────┘   └────────────────┘
                         두 축이 만나는 지점 = 부서 · business_code
```

- `task_code`가 마스터 키다. S/G/E·handler·business_code가 여기서 파생된다.
- **S/G/E는 검색에 쓰이지 않는다.** 검색 SQL 필터는 `category`(부서·business_code) 하나뿐이다.
- 문서에는 `task_code`를 붙이지 않는다. 문서 1건이 여러 용건에 답하기 때문이다(N:1).

## 2. 신규 제안 코드 3개

기존 `G001~G010` 다음 번호를 이어 붙였다. **부서·S/G/E·handler 규칙은 그대로**라 라우팅 구조 변경이 없다.

| task_code | 업무 | 부서 | business_code | 왜 필요한가 |
|---|---|---|---|---|
| `G011` | 주택청약 상담 | DEP | `subscription` | 청약 문서 5건(180청크)에 도달할 코드가 없었다 |
| `G012` | 연금·IRP 상담 | INV | `pension` | IRP 문서 1건(29청크)에 도달할 코드가 없었다. INV의 유일한 코드 |
| `G013` | 카드 이용 상담 | CRD | `card` | CRD에 사람 상담 코드가 없어 카드 복합 상담을 배정할 수 없었다 |

전부 `G`(일반·`HUMAN`)로 둔 이유: 상담사 판단이 필요한 업무이고, 신규 `S`(자동처리) 추가는
AI 응답 범위를 넓히므로 근거 문서 확보 후 검토하는 것이 안전하다.

**선택 사항** — 필요하면 나중에 추가할 수 있는 자동처리 코드:
`S007 청약 납입내역 조회`(DEP/`subscription`). S001·S002와 성격이 같은 전형적 ARS 업무다.

## 4. 남은 문제

### ✅ 해결됨 — 도달 불가 문서 0건
신규 코드 3개로 `subscription`(5건)·`pension`(1건)이 검색 경로에 연결됐다.
전처리는 끝났는데 부를 코드가 없던 문서 209청크가 살아난다.

### 🔴 남은 문제 — 코드 23개에 문서가 없다
`card`(18) · `efn`(3) · `general`(2). 전체 38개 중 **61%**.
특히 `card`는 17개가 `AI_CC`(자동응답)라 **근거 문서 없이 AI가 답하는 구조**다.

### ⚠️ DEP `deposit`이 빈약하다
배정 코드 5개(잔액·거래내역·자동이체·만기해지)가 걸려 있는데 문서는 `발행어음` 1건·청크 3개뿐이다.
정기예금·정기적금·자유적금 설명서 확보가 필요하다.

### ⚠️ LON 편중
문서 21건·청크 880개로 코퍼스의 76%가 대출에 몰려 있다.
