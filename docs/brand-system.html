PART 0

브랜드

B1

왜 KARI-NA인가 — 이름의 뜻

키움 아카데미 교육 과정에서 태어난 이름입니다. 다섯 조각의 머리글자를 모았고, 마지막 두 글자가 곧 제품의 차별점입니다.

KKiwoom키움
AAcademy아카데미
RResponse응대
IInnovation혁신
NANo ARSARS 없음

가운데 Response · Innovation 이 태그라인 “Response Innovation”이 되고, 끝의 NA = No ARS가 정체성의 핵심입니다.

B2

정체성 — No ARS

“1번을 누르세요” 식 버튼 트리를 없앴습니다. 고객이 자연어로 말한 한 문장이 전체 파이프라인의 유일한 입력이 됩니다.

✕ 기존 ARS
“상담원 연결은 0번…”
“대출은 1번, 카드는 2번…”
“다시 들으시려면 별표…”
→
✓ KARI-NA
“대출 한도를 올리고 싶은데요.”
한 문장 → 부서·업무·확신도·근거까지 자동 라우팅.

태그라인 Response Innovation — 응대(Response)의 방식을 다시 짓는다(Innovation).

B3

성격 & 가치

정체성에서 도출한 네 가지 성격입니다. 아래 디자인 언어(PART 2)의 근거가 됩니다.

즉시성

Immediate

버튼 트리·대기음 없이 첫 문장부터 처리. 기다림을 없앤다.

신뢰

Trust

금융의 언어. 정확하고 일관되며 근거를 보여주는 응대.

명확

Clarity

지금 무슨 일이 일어나는지 한눈에. 상태를 숨기지 않는다.

차분

Composed

관제실의 침착함. 과장·소란 없이 통제감 있게.

※ 이름·No ARS·태그라인은 확정 사실. 위 성격·가치·보이스는 거기서 도출한 제안이니 검토 후 확정하세요.

B4

브랜드 → 디자인 — 왜 이렇게 생겼나

브랜드 가치가 각각 어떤 디자인 결정으로 이어지는지. 이 매핑이 “새로 더해도 같은 톤”의 실제 근거입니다.

B5

보이스 & 톤 — 어떻게 말하나

No ARS의 언어. 버튼 트리처럼 지시하지 않고, 사람처럼 차분하고 정확하게 말합니다.

01

사람처럼

“1번을 누르세요”가 아니라 자연스러운 한국어로. 기계 안내 말투 금지.

02

군더더기 없이

한 번에 핵심만. 반복 안내·대기 멘트·불필요한 사과 없음.

03

근거를 보이며

부서·업무·확신도·근거를 함께. 왜 그렇게 판단했는지 드러낸다.

04

상태는 사실대로

처리중·완료·실패를 숨기지 않는다. 사과 대신 다음 행동을 제시.

✕ 이렇게 말하지 않는다
“죄송합니다. 문의하신 내용은 상담원 연결이 필요합니다. 잠시만 기다려 주시면…”
“대출 관련은 1번, 카드는 2번을 눌러주세요.”
→
✓ 이렇게 말한다
“대출 한도 상담이네요. 상담팀으로 바로 연결할게요.”
확신도 92% · 근거: 발화 “한도 상향” · 대출상담팀

※ 보이스는 정체성(No ARS)에서 도출한 제안입니다 — 실제 카피 가이드로 확정 시 예시 문장을 늘려가세요.

PART 2

ONAIR 디자인 언어

10

원칙

K7 직원용 관제 화면의 디자인 언어입니다. 전문·중성 톤, 절제된 색, 그림자로 그리는 위계 — 다섯 원칙으로 요약됩니다.

01 · ELEVATION

빛은 그리지 않는다, 그림자가 그린다

그라데이션·글로우를 쓰지 않습니다. 위계·경계·맞물림은 중성 잉크 그림자(near·hover·focus·joint·modal)가 만듭니다. 거리감은 그림자가 아니라 잉크 투명도가 맡습니다.

02 · SURFACE

면은 쿨 뉴트럴 한 색

패널은 석고 화이트 한 색, 바닥은 석고벽 그레이. 웜 캐스트 없는 중성 회색으로 관제실의 전문적인 톤을 만듭니다.

03 · COLOR

색은 점·글자·가는 요소에만

큰 면은 중성으로 두고, 색은 신호등 램프(점)·텍스트·가는 선에만 씁니다. 블루=행동, 앰버=켜진 램프, 빨강·초록=신호 점.

04 · THEME

라이트 온리

회사 내부 관제용 프로그램으로 다크 모드는 지원하지 않습니다. 단일 밝은 환경에 최적화합니다.

05 · GRID · MOTION

4px 그리드 · 절제된 모션

모든 간격은 4px 배수. 모션은 변화를 설명할 때만, 바운스(오버슈트) 없이 — 금융 콘솔의 성격에 맞춰 차분하게.

CONTINUITY

로고 블루 = 시스템 블루

로고의 #2F5FC4 는 디자인 시스템의 --blue-700(행동색)과 완전히 동일합니다. 브랜드와 제품이 같은 파랑을 공유합니다.

적용 순서 & 참조 철학

이 문서의 목적은 하나 — 무엇을 새로 추가해도 자동으로 같은 톤이 나오게 하는 것. 아래 순서로 위계를 세우면, 색과 그림자를 거의 안 써도 화면이 ONAIR처럼 앉습니다.

위계는 이 순서로 — 색은 최후의 수단
1 · 타이포 크기·weight→ 2 · 스페이싱 4px 그리드→ 3 · 그림자 높이→ 4 · 색 점·글자·가는 선
“Design in monochrome. Use color only when it adds meaning.”— vercel.com/design.md · ONAIR의 뿌리

면(surface)은 벌어서 씁니다 — 선택·상호작용·경고·실제 그룹을 표현할 때만 카드·경계를 두고, 스페이싱으로 될 일은 스페이싱으로. 모든 섹션을 카드로 감싸지 않습니다. 상태에는 항상 색 + 비색 단서를 함께(색맹 안전).

지양 — 이건 우리 언어가 아님

토큰 — 그대로 복붙

새 화면·컴포넌트는 아래 변수만 var(--*)로 참조합니다. raw hex를 직접 쓰지 않으면 색·간격·형태가 저절로 맞습니다. (전체 원본: src/styles/tokens.css)

/* ── ONAIR tokens (요약) — 컴포넌트는 이 alias만 참조 ── */ :root{ /* Surfaces — 석고 화이트 패널 · 석고벽 그레이 바닥 */ --floor:#e9eaeb; --surface:#ffffff; --surface-2:#f8f9f9; /* Gray — 쿨 뉴트럴 (텍스트·면) */ --gray-100:#eef0f1; --gray-400:#d7d9dc; --gray-600:#83878c; --gray-700:#6b6f74; --gray-900:#4d5156; --gray-1000:#1b1d20; /* Accents — 점·글자·가는 선에만 */ --blue-700:#2f5fc4; /* 행동/전경 · 로고 블루와 동일 */ --amber-700:#dfa348; /* 켜진 램프 */ --red-700:#bc3f2b; --green-700:#3e7a4e; /* 신호 점 */ /* Semantic — 컴포넌트는 여기부터 참조 */ --color-bg:var(--surface); --color-fg:var(--gray-1000); --color-fg-muted:var(--gray-700); --color-border:rgba(20,23,28,.12); --color-link:var(--blue-700); --color-focus:var(--blue-700); --color-success:var(--green-900); --color-danger:var(--red-900); --color-warning:var(--amber-900); /* Type — 라틴=Avenir · 한글=Pretendard · 숫자/데이터=Geist Mono */ --font-display:"Avenir Next","Pretendard",system-ui,sans-serif; --font-mono:"Geist Mono",ui-monospace,Menlo,monospace; /* Space (4px 그리드) · Radius · Elevation · Motion */ --space-2:8px; --space-4:16px; --space-8:32px; --radius-sm:6px; --radius-md:12px; --radius-inner:8px; --radius-full:9999px; --sh-near:0 3px 8px -3px rgba(15,18,24,.25), 0 1px 2px rgba(15,18,24,.10); --sh-modal:0 2px 4px rgba(15,18,24,.14), 0 18px 40px -10px rgba(15,18,24,.35); --ease-out:cubic-bezier(.2,.8,.2,1); --duration-state:150ms; }

새 UI 추가 체크리스트

화면·컴포넌트를 붙이기 전에 이 열 가지를 통과하면 ONAIR 톤에서 벗어나지 않습니다.

✓
semantic alias만 — raw hex 직접값 0개, 전부 var(--*)
✓
큰 면은 중성 — 색은 점·글자·가는 선에만
✓
위계가 타이포로 먼저 — 색·그림자 빼도 읽히나(squint test)
✓
4px 그리드 위 — 오프-스케일 간격 없음
✓
반지름 한 가족 — 패널12·타일8·컨트롤 pill 섞지 않기
✓
surface는 벌어서 — 불필요한 카드·카드 속 카드 없음
✓
그라데이션·글로우·베벨 0 — 위계는 그림자(높이)로만
✓
테두리는 전체 균일 — 한쪽만 색 넣는 side rail 금지
✓
상태엔 색+비색 단서 — 점/아이콘/텍스트 동반
✓
서체 역할대로 — 라틴 Avenir · 한글 Pretendard · 숫자 Geist Mono
✓
모션은 필요한 곳만 — ease-out, 바운스·패럴랙스 없음
