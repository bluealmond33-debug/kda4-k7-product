## 배경

백엔드 검토안(2026-07-24)이 감정온도·사고징후 처리를 재정의했다. 문서는 11절에서 3단계로 나뉘며,
이 스펙은 **1단계만** 다룬다. 2단계(감정+숙련도 라우팅)·3단계(성과·교육)는 상담사 DB와 실적
데이터가 없어 7/29까지 불가하다(문서 6절·10절 Q8이 부재를 인정). 1단계 안에서도 "첫 응대 문장
감정 연계"(1c)는 별도 픽스처 문제와 겹쳐 이식 이후 `customer_request_points` 작업과 합쳐 처리한다.

즉 이 스펙의 범위는 **프론트 전용, 계약 무변경, 이식과 무충돌**인 두 가지다.

1. 상담 준비 화면의 "사고 징후(위험도)" 카드 제거
2. 감정온도 3단계 표시 라벨 정리

## 현재 상태 (2026-07-24 실측)

- 감정온도는 **이미 3밴드 구조**다. 계약 `emotion.level ∈ {stable, caution, elevated}`,
  점수 밴드 0–33 / 33–66 / 66–100. 검토안의 GREEN/YELLOW/RED = 안정/주의/집중대응은 이
  3밴드의 재명명이지 새 모델이 아니다.
- 라벨 매핑: `EMOTION_LABELS = { stable: "안정", caution: "주의", elevated: "고조" }`
  (`src/hooks/useCallFlow.ts:167`). **`elevated`가 "고조"** 로 되어 있다.
- 사고징후 카드는 두 곳에 렌더된다.
  - `PrepCard.tsx:128–137` — 좌측 [감정온도]+[사고징후] 세로 스택(238px)의 아래 카드. 위험 시
    빨강(`riskHigh`), "높음" + 신호 텍스트(`prepRiskSignal`) 표시.
  - `ActiveCall.tsx:149–152` — 통화 중 가로 스탯바의 인라인 항목(아이콘 + "사고 징후" + 라벨).
- 헤더 긴급 배지 "긴급 · 사고 징후 감지"(`PrepCard.tsx:36`)는 콜 유형이 긴급일 때만 표시된다.

## 결정

### 1. 사고징후 카드 제거

검토안 4절: 사고징후·위험도 카드는 UI에서 제거하되, 금융사고 탐지와 긴급 라우팅은 백엔드
정책으로 유지한다.

- `PrepCard.tsx`의 "사고 징후(위험도)" 카드 블록(128–137) **삭제**.
- `ActiveCall.tsx`의 인라인 사고징후 항목(149–152)과 그 앞 구분선 **삭제**. 스탯바는
  `감정 | 시계`로 남는다.
- 헤더 긴급 배지 "긴급 · 사고 징후 감지"(`PrepCard.tsx:36`)는 **문구 그대로 유지**한다.
  이 배지는 긴급 콜에만 뜨는 라우팅 신호(`vm.isUrgent`)로, 상시 표시하던 위험도 카드와 역할이
  다르다. 배지에 "사고 징후" 문구가 남지만 카드 제거와는 별개다. (변경 최소화)
- 백엔드 judge·금융사고 탐지·긴급 라우팅은 **건드리지 않는다**. 화면 표시(카드)만 제거한다.

> 백엔드가 계속 보내는 `incident_risk`·judge 결과는 프론트가 더 이상 카드로 그리지 않을 뿐,
> 긴급 배지(`vm.isUrgent`)의 근거로는 계속 쓰인다. 계약 필드는 그대로 둔다.

### 2. 빈 좌측 공간 → 감정온도 안내문구

사고징후 카드가 빠진 좌측 238px 하단에 검토안 3절의 안내문구를 넣는다.

> 감정온도는 음성·발화 내용을 기반으로 산출한 상담 보조지표입니다. 고객의 실제 감정이나
> 위험 여부를 확정하지 않습니다.

이는 검토안 3절 "표현 원칙"(고객을 위험·분노로 단정하지 않음)을 화면에 직접 구현하는 것이다.
빈 카드 자리를 메우면서 동시에 감정온도의 성격을 명시한다.

`ActiveCall`의 가로 스탯바에는 공간이 없으므로 안내문구를 넣지 않는다. 사고징후 항목만 제거한다.

### 3. 감정온도 3단계 라벨

- `EMOTION_LABELS`의 `elevated: "고조"` → **`elevated: "집중 대응"`**.
- `stable: "안정"`, `caution: "주의"`는 그대로 둔다(검토안과 일치).
- **계약(wire)은 `stable/caution/elevated`를 유지한다.** 검토안이 말한 "내부 코드"가 곧 이
  값이며, 화면 표시 라벨만 바뀐다. `contracts.py`·JSON 스키마·파서는 손대지 않는다.
- 색 바인딩(초록/앰버/빨강)은 유지한다.

## 테스트

프론트에는 단위 테스트 러너가 없다. 검증은 다음으로 한다.

- `npm run check` 통과 (manifest·contracts·adapter·frontend-contract·build). 계약을 안 바꾸므로
  `validate:*`는 그대로 통과해야 한다 — 통과하면 계약 무변경이 증명된다.
- 프론트 E2E: 시연 WAV 업로드 → 준비 카드에 **사고징후 카드가 없고** 좌측에 **안내문구**가
  있으며, 감정 라벨이 밴드에 맞게(고조 대신 **집중 대응**) 표시되는지 육안 확인.
- 통화 단계 진입 → `ActiveCall` 스탯바에 사고징후 항목이 없는지 확인.
- 긴급 시나리오(수신 토글 긴급) → 헤더 배지가 **"긴급 · 사고 징후 감지"** 로 그대로 뜨는지 확인.
